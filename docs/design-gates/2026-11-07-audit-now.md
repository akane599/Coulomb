## Findings

**[P2] Chart labels shrink at narrow widths**
- **Location:**
  - `now.html`, the hero projection (`<!-- chart:now-projection -->`) and the live current chart;
  - `tools/build.py`, `now_projection()` and `now_current()`.
- **Category:** Responsive.
- **Impact:** at 360 px the 10 px axis labels ("−2 h", "100%", "−1,200") render at about 8.6 px, too small to read at arm's length.
- **Standard:** SPEC 11 type scale (chart labels at least 11 sp in the port).
- **Recommendation:**
  - Lab: keep the viewBox at 380 for the 412 reference.
  - Port: Compose `Canvas` text uses `TextMeasurer` in sp at native size, and the plot width follows the container, so labels do not scale.
  - Record this in DESIGN.md as a chart rule.
- **Suggested command:** `/impeccable adapt`.

**[P3] Buttons were 40 px tall with a 40 px hit area (fixed)**
- **Location:** `lab.css`, `.btn`. Affected "Restrict background" and "Open battery protection".
- **Category:** Accessibility.
- **Impact:** the visual height matches Material 3, but the hit area was below 44 px.
- **Standard:** WCAG 2.5.8 (24 px minimum) was met. Material's 48 dp touch target was not.
- **Fix applied:** `.btn::before { inset: -4px 0 }` extends the hit area to 48 px without changing the visual. Compose gets the same from `minimumInteractiveComponentSize`.

**[P3] Fonts block rendering**
- **Location:** `lab.css`, `@font-face` (`font-display: block`).
- **Category:** Performance.
- **Impact:** none for local files; the setting is deliberate so captures never show fallback metrics. Android bundles the fonts in `res/font`, so it does not apply to the app.
- **Recommendation:** keep it for the lab and note it in DESIGN.md.

## Patterns and systemic issues

- **Charts:** every chart is a fixed-viewBox SVG, so all chart labels share the narrow-width shrink. A single port rule resolves it.
- **No sub-44 px targets remain:** button groups and buttons now share the 48 px hit-area rule.
